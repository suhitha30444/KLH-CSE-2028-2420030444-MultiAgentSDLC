# /data

This project has no static training dataset. Its input is an arbitrary
plain-English software requirement, typed in at runtime (e.g. "build a
ShoppingCart class with add/remove items and a percentage discount"). The
Planner agent turns that requirement into a structured, Pydantic-validated
spec (requirement text + explicit acceptance criteria + tasks), which a
human then approves before any code is generated.

**Data source reference:** concrete examples of real requirements-turned-specs,
generated by actual pipeline runs (some in mock mode, some against live
Groq calls), are committed under [`/results/specs`](../results/specs) —
each `spec_<run_id>.json` file is one real Planner output. The
corresponding generated code and traceability reports for those same runs
are under [`/results/code`](../results/code) and
[`/results/reports`](../results/reports).

Literature reviewed while designing the multi-agent approach (ChatDev,
MetaGPT, AgentCoder, and related work) is under [`/docs`](../docs).
